# Локальная модель и Ollama: техническая лабораторная

Эта глава — опциональная техническая справка, а не обязательная вводная неделя курса. Для пошаговой настройки Ollama, VS Code Chat и Kilo см. отдельный [справочник интеграции](ollama-vscode.md). Ниже оставлены rationale выбора модели и ограничения по ресурсам для сопоставления результатов лабораторных.

## Что можно ожидать от 14 ГБ RAM и Ryzen с 8 потоками

По числу потоков и объёму оперативной памяти нельзя точно предсказать скорость: неизвестны конкретный CPU, видеокарта и её VRAM, тип памяти, доступная память после запуска VS Code и ОС, а также длина контекста. Ниже предполагается **14 ГБ системной RAM и преимущественно CPU-инференс**. Если у вас есть дискретная GPU, сообщите модель и VRAM — выбор может измениться.

Для такого компьютера локальная модель годится для экспериментов с короткими агентными задачами, структурированными ответами и отдельными изменениями. Это **не** эквивалент Claude/Kilo cloud и не комфортный запуск рекомендованных Kilo больших coding-agent моделей.

### Модели для первого сравнения

1. **Начать с `qwen3:8b`** — кандидат на общий локальный чат и вызовы инструментов. Официальная страница семейства Qwen3 описывает поддержку агентных сценариев. Начните с контекста 8K и одиночного запроса, прежде чем подключать агента, который читает репозиторий.
2. **Сравнить с `qwen2.5-coder:7b`** — отдельный кандидат для Python-генерации, объяснения и правок кода. Не считать автоматически надёжным Kilo tool-calling агентом: проверить вызов инструментов конкретной версией модели.

Эти команды указаны на страницах моделей Ollama. Точный тег и доступность могут меняться; проверьте актуальные страницы перед скачиванием: [Qwen3](https://ollama.com/library/qwen3) и [Qwen2.5-Coder](https://ollama.com/library/qwen2.5-coder).

```powershell
ollama pull qwen3:8b
ollama run qwen3:8b
```

Завершить интерактивную сессию Ollama: `/bye`. Затем, если есть место и желание сравнить именно кодовую модель:

```powershell
ollama pull qwen2.5-coder:7b
ollama run qwen2.5-coder:7b
```

**Не начинайте с `qwen3-coder:30b`, `devstral:24b` или моделей с похожими требованиями.** Документация Kilo называет их текущими рекомендациями для локального coding agent и указывает ориентир GPU VRAM 24 ГБ+ либо Mac с 32 ГБ unified memory. Это не соответствует исходной конфигурации 14 ГБ системной памяти. Не путайте оперативную память компьютера с VRAM видеокарты.

У `qwen3:8b` и `qwen2.5-coder:7b` квантование, размер контекста и реальный расход памяти влияют на помещаемость модели. Оставьте память ОС, VS Code и другим приложениям; если Windows начинает активно использовать файл подкачки, модель тормозит или не загружается, уменьшите модель/контекст или завершите другие задачи. Не обещаем конкретную скорость без измерения на вашем Ryzen.

### Контекст для вашего объёма RAM

Для первого Kilo-теста попробуйте **8 192 токена (8K)**; если устойчиво хватает памяти — **16 384 (16K)**. Это практический компромисс, не «идеальный контекст» и не рекомендация Kilo для больших репозиториев. Kilo указывает, что для обсуждаемых им крупных моделей желательно не менее 32K, однако 32K на 14 ГБ системной RAM может привести к нехватке ресурсов. Длинный контекст требует дополнительной памяти, а не только места для весов модели.

Для агента со сканированием репозитория лучше сузить контекст за счёт явного списка файлов и короткого запроса, чем сразу увеличивать его до 32K. Не запускайте несколько локальных генераций параллельно на CPU, пока не измерили, что компьютер справляется.

# Практикум 0. Установка Ollama и диагностика на Windows

> **Справочный раздел.** Его можно пропустить, если локальная модель уже подключена. Для быстрого прохождения используйте [справочник Ollama/VS Code/Kilo](ollama-vscode.md), где собраны основные шаги и диагностика.

Этот раздел — отдельная техническая лабораторная. Он разбирает распространённую путаницу: модель может отвечать в приложении Ollama, но не быть добавленной в нужный чат VS Code или не быть выбрана как провайдер Kilo.

## 0.1 Установка и проверка службы

1. Установите Ollama с [официального сайта](https://ollama.com/download).
2. Запустите приложение Ollama. В Windows оно обычно поднимает локальную службу в фоне.
3. Откройте PowerShell и проверьте CLI:

   ```powershell
   ollama --version
   ollama list
   ```

4. Если модели ещё нет, скачайте одну из рекомендованных выше. После скачивания повторите `ollama list`.
5. Проверьте, что локальный HTTP API отвечает:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:11434/api/tags
   ```

   В JSON должен быть список моделей. Можно также проверить OpenAI-совместимый маршрут:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:11434/v1/models
   ```

6. Загрузите модель отдельным smoke test:

   ```powershell
   ollama run qwen3:8b
   ```

   Введите короткий запрос, дождитесь ответа и выйдите командой `/bye`.

Установка приложения, наличие скачанных весов и доступность API — три разные вещи. Запросы в `/api/tags` и `/v1/models` проверяют, что VS Code/Kilo в принципе может увидеть службу и модель.

### Полезные команды Ollama

```powershell
ollama list                 # скачанные модели
ollama ps                   # модели, сейчас загруженные в память
ollama show qwen3:8b        # сведения о модели
ollama pull qwen3:8b        # скачать/обновить модель
ollama run qwen3:8b         # интерактивный чат в терминале
```

Внутри интерактивного чата `ollama run` команда `/show info` показывает сведения о загруженной модели, `/bye` завершает диалог. `pull` только загружает веса; `run` запускает диалог. Отдельное `ollama serve` обычно не нужно, если приложение уже запустило сервер.

Если хотите закрепить настройки контекста за отдельным тегом модели, создайте текстовый файл с именем `Modelfile` в удобной папке:

```text
FROM qwen3:8b
PARAMETER num_ctx 8192
PARAMETER temperature 0.2
```

Затем в этой папке:

```powershell
ollama create qwen3-8b-ctx8k -f .\Modelfile
ollama run qwen3-8b-ctx8k
```

Новый тег использует исходные веса `qwen3:8b`, но задаёт меньший контекст по умолчанию. Для Kilo всё равно задайте согласованный лимит контекста в настройках провайдера. Если используете 16K, создайте отдельный тег с `PARAMETER num_ctx 16384` и сначала проверьте расход памяти.

## 0.2 Когда нужен `ollama serve`

На Windows приложение Ollama часто уже запустило сервер. **Не запускайте второй сервер вслепую.** Если `http://127.0.0.1:11434/api/tags` отвечает, сервер уже работает; отдельная команда `ollama serve` обычно сообщит, что порт занят. Запускайте её вручную только если приложение/служба не запущена и вы осознанно хотите видеть серверные логи в отдельном окне PowerShell. Это окно нужно оставить открытым.

Ollama по умолчанию привязывается к localhost. Для VS Code и Kilo на том же компьютере не нужно открывать API в локальную сеть или интернет и не следует менять bind на `0.0.0.0`.

## 0.3 Две разные интеграции в VS Code

### Вариант A: модель в собственном чате VS Code от Ollama

Это путь, если хотите видеть ответы в **VS Code Chat**, а не только в приложении Ollama:

1. Убедитесь, что Ollama запущена, `ollama list` показывает модель, а `/api/tags` отвечает.
2. В VS Code откройте Extensions и установите официальное расширение **Ollama** из Marketplace: [Ollama extension](https://marketplace.visualstudio.com/items?itemName=Ollama.ollama).
3. Откройте панель Chat в VS Code.
4. В меню выбора модели снизу чата выберите модель из группы **Ollama**.
5. Если список пуст: откройте Command Palette (`Ctrl+Shift+P`) → `Ollama: Refresh Models`; затем `Ollama: Diagnose Models`; проверьте канал вывода **Ollama**.

По актуальной инструкции Ollama это расширение требует VS Code 1.127 или новее и обнаруживает локальные модели по `http://127.0.0.1:11434`. Это интеграция с VS Code Chat; она не делает модель автоматически активной в Kilo.

### Вариант B: модель в чате и режимах Kilo Code

Если хотите, чтобы отвечал именно **Kilo**, нужно выбрать Ollama как провайдера внутри Kilo:

1. Убедитесь, что endpoint работает:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:11434/api/tags
   ```

2. В панели Kilo откройте выбор модели/настройки провайдера (иконка настройки/gear).
3. В списке **API Provider** выберите **Ollama** — не **Ollama Cloud**. Cloud — удалённый сервис; он не подключается к `localhost`.
4. В поле локального base URL укажите `http://127.0.0.1:11434` (если поле показывается; это стандартный локальный адрес).
5. Выберите или введите точное имя модели, как показывает `ollama list`, например `qwen3:8b`.
6. Установите контекст сначала `8192`; если тест показывает, что память позволяет — попробуйте `16384`.
7. Увеличьте **API Request Timeout** в настройках Kilo, если локальный CPU-инференс не успевает в стандартные 10 минут. Начните, например, с 20 минут, но не маскируйте зависшую генерацию бесконечным таймаутом.
8. Сохраните настройки и выберите эту модель для текущего режима/сессии Kilo.
9. Проверьте в коротком чате обычный ответ, затем отдельным минимальным заданием проверьте tool calling. Не сразу давайте Kilo право менять большой репозиторий.

У Kilo есть отдельная инструкция [Using Ollama With Kilo Code](https://kilo.ai/docs/ai-providers/ollama). Если модель не появилась в picker, документация Kilo позволяет добавить custom model в конфигурацию. Пример ниже задаёт модель и лимиты; вставлять его следует в конфиг Kilo, который открыт из настроек, а не в `settings.json` VS Code:

```json
{
  "model": "ollama/qwen3:8b",
  "provider": {
    "ollama": {
      "models": {
        "qwen3:8b": {
          "name": "Qwen3 8B (local)",
          "tool_call": true,
          "limit": {
            "context": 8192,
            "output": 2048
          }
        }
      }
    }
  }
}
```

`tool_call: true` сообщает Kilo, что модель следует использовать как поддерживающую вызов инструментов; это **не** гарантирует, что конкретный тег хорошо вызывает инструменты. Удалите/не добавляйте этот флаг, если модель фактически не справляется с вызовами. Проверьте схему настроек Kilo и формат custom model в [Custom Models](https://kilo.ai/docs/code-with-ai/agents/custom-models) на установленной версии: конфигурация продукта может меняться.

## 0.4 Отдельно: подключение через OpenAI-compatible API

Провайдер **Ollama** в Kilo предпочтительнее, если он доступен: меньше ручной настройки. Если другой инструмент умеет только OpenAI-compatible API, Ollama документирует локальный endpoint:

```text
Base URL: http://127.0.0.1:11434/v1
API key: ollama
Model: точное имя из ollama list, например qwen3:8b
```

Значение `ollama` здесь — совместимый заполнитель: локальный сервер игнорирует API key. Не путайте endpoint `/v1` с интерфейсом провайдера Kilo Ollama, которому обычно указывается сам базовый адрес.

Короткая проверка из Python (по документации Ollama OpenAI compatibility):

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:11434/v1",
    api_key="ollama",
)

response = client.chat.completions.create(
    model="qwen3:8b",
    messages=[{"role": "user", "content": "Ответь одной строкой: локальный API работает"}],
)
print(response.choices[0].message.content)
```

Пакет: `python -m pip install openai`. Перед использованием в Kilo сначала добейтесь успешного ответа этим тестом или проверкой `/v1/models`.

## 0.5 Диагностика по симптому

| Симптом | Проверка / действие |
|---|---|
| `ollama` не распознана в PowerShell | Перезапустите терминал после установки; проверьте установку приложения и его PATH. |
| `/api/tags` не отвечает | Запустите приложение Ollama; проверьте, не остановлена ли служба. Не открывайте порт наружу. |
| API отвечает, но моделей нет | `ollama list`; при отсутствии модели — `ollama pull <точный-тег>`. |
| Модель отвечает в приложении Ollama, но отсутствует в VS Code Chat | Установите Ollama VS Code extension, проверьте версию VS Code, выполните Refresh Models и Diagnose Models. |
| VS Code Chat видит модель, Kilo — нет | Это независимые интеграции. В Kilo отдельно выберите API Provider = Ollama и локальную модель. |
| Kilo не соединяется | Проверьте, что выбран локальный **Ollama**, не Ollama Cloud; проверьте адрес localhost, затем проверьте `/api/tags`. |
| Kilo отвечает текстом, но не выполняет tools | Проверить режим Kilo, tool-call поддержку/настройку модели и минимальный tool test; не считать обычный ответ доказательством поддержки tools. |
| Запрос зависает/ошибка таймаута | Сократите контекст и промпт, отключите MCP на проверку, увеличьте API Request Timeout умеренно, измерьте время. |
| Компьютер начинает свопить | Закройте лишние приложения, снизьте контекст, оставьте одну модель/один запрос, попробуйте меньший размер. |
